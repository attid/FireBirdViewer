# 016: Agent change approval gate

## Контекст

Репозиторий требует exec-plan перед нетривиальными задачами, но не содержит
корневого `AGENTS.md` и не требует явно согласовать с человеком точный список
файлов до начала изменений. В результате агент может перейти от диагностики к
правкам без ожидаемого checkpoint.

Пользователь подтвердил этот план и список файлов сообщением `++`.

## План изменений

1. [x] Создать корневой `AGENTS.md` с обязательным approval gate для любых
   изменений файлов.
2. [x] Зафиксировать формат chat-plan: цель, шаги, точный список файлов,
   проверки и риски.
3. [x] Требовать повторное подтверждение при расширении scope.
4. [x] Синхронизировать `AI_FIRST.md` и `CLAUDE.md` с новым процессом.
5. [x] Проверить документацию и выполнить `just check`.
6. [x] Перенести этот план в `docs/exec-plans/completed/`.

## Согласованный список файлов

- Создать `AGENTS.md`.
- Изменить `AI_FIRST.md`.
- Изменить `CLAUDE.md`.
- Создать `docs/exec-plans/active/016-agent-change-approval.md`.
- После выполнения перенести план в
  `docs/exec-plans/completed/016-agent-change-approval.md`.

Другие файлы изменять запрещено без повторного подтверждения пользователя.

## Риски и открытые вопросы

- CI не может доказать, что человек подтвердил план в чате. Основной механизм
  соблюдения правила — автоматически загружаемый агентом `AGENTS.md`.
- Read-only диагностика должна оставаться доступной до подтверждения, иначе
  агент не сможет подготовить обоснованный план.

## Верификация

- `AGENTS.md` существует в корне и содержит явные слова `STOP` и
  `explicit approval`.
- `AI_FIRST.md` и `CLAUDE.md` ссылаются на один и тот же approval workflow.
- Документы требуют точный список файлов и повторное согласование scope.
- `just check` проходит.
